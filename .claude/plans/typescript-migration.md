# TypeScript migration (plain JS -> strict TS, tsc to dist/, no bundler)

## Layout (already set up by the lead)
- All sources moved to `src/` and renamed `.ts` (CONTENT IS STILL JAVASCRIPT; converting it is the job). Static files (html/css) are in `src/` too and copied by the build.
- `tsconfig.base.json` (strict), `tsconfig.main.json` (module node16/CommonJS, lib ES2023, types node; includes `src/*.ts`, `src/providers`, `src/shared`, `src/scripts`, `src/types/**/*.d.ts`; excludes `src/renderer`), `tsconfig.renderer.json` (module none, lib DOM, no node types; includes `src/renderer/**` and `src/types/**/*.d.ts`).
- `scripts/build.js` (plain JS, the only exception) runs both tsc projects, then copies non-.ts files from `src/` and `assets/icon.png` into `dist/`. `package.json`: `main` = `dist/main.js`, `npm run build`, `npm run typecheck`.
- Runtime layout `dist/` mirrors `src/`. So `dist/renderer/index.html` reaches `node_modules` as `../../node_modules/...`; anything resolving a path to `node_modules/`, `vendor/`, `build/` or the project root from `__dirname`/relative URLs must be re-based (grep `node_modules` and `vendor/` in your files). `assets/icon.png` is copied to `dist/assets/icon.png`, so `__dirname/assets/icon.png` still works.

## Rules for every converted file
1. Strict mode, NO `any` (explicit or via `as any`), no `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`, no non-null `!` abuse. Use precise types, `unknown` + narrowing, generics, discriminated unions. Define named interfaces/types for IPC payloads, settings, tabs, ctx, etc. Export types that other files need (`export interface ...`).
2. Behaviour must stay IDENTICAL. Do not refactor, rename or change logic; only add types and the minimum code needed for the compiler (e.g. null checks that keep the same runtime result). Keep comment density and style; convert JSDoc `{type}` annotations into TS annotations and drop the now-redundant JSDoc types (keep descriptions).
3. Main-process files (CommonJS emit): replace `require`/`module.exports` with `import`/`export` EXCEPT where a lazy/optional/conditional `require` or dynamic `import('node-llama-cpp')` is intentional (keep it; type the result with `typeof import(...)`). Keep `'use strict'` out (tsc emits it). Keep the module's public API names and shapes. Files loaded via `utilityProcess.fork`, `Worker`, `preload`, `loadFile` keep their emitted names (`.js` in dist, same relative path).
4. Renderer files are classic scripts (no imports/exports; wrapped in IIFEs; talk through `window.CodePad*` globals). Keep them scripts: no top-level import/export. All cross-file types come from global declarations in `src/types/*.d.ts` (ambient `declare global` / `interface Window`). Because tsc cannot see other script files' IIFE internals, every global (`window.codepad`, `CodePadBus`, `CodePadCommands`, `CodePadUI`, `CodePadPanels`, `CodePadFeatures`, `CodePadEditors`, `CodePadSettings`, `CodePadThemes`, `ctx`, libraries like `XLSX`, `pdfjsLib`, `mammoth`, `docx`, `PDFLib`, `monaco`) must be declared once in a `.d.ts`. Monaco: `/// <reference path="../../node_modules/monaco-editor/monaco.d.ts" />` style reference in a d.ts.
5. Shared UMD files (`src/shared/*.ts`) stay usable both via Node `require` and as renderer `<script>` (they set `root.CodePadX` when `module` is absent). Compile them only in the main project (node types); keep the UMD wrapper behaviour; type the renderer-side global through `src/types` (e.g. `typeof import('../shared/searchCore')`-style declarations).
6. Do not touch other agents' files. If you need a type that belongs in another agent's file, import it (main side) or declare it in `src/types/<area>.d.ts` that you own, and say so in your report.
7. Run only: `node node_modules/typescript/bin/tsc -p tsconfig.main.json --noEmit` and/or `-p tsconfig.renderer.json --noEmit`, filtering output to your files (`| grep "^src/<yourpaths>"`). Other agents work concurrently, so errors in their files are not yours. Do NOT run the app, npm scripts, builds, tests, git or anything long-running. Iterate until your files have zero errors, then re-run once more to confirm.
8. Remove nothing that is still used. Update header comments that mention `.js` names. Final report (short): files done, new d.ts files and exported types, any behaviour-relevant change, remaining errors (should be none) and anything the lead must wire.
