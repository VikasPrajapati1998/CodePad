# CodePad Project Knowledge

- Stack: Electron + Monaco editor, strict TypeScript in `src/` compiled by tsc to `dist/` (no bundler, no framework; `main` is `dist/main.js`). Never edit `dist/`. No `any`, `@ts-*` or non-null shortcuts; renderer files stay classic scripts typed through ambient `src/types/*.d.ts`; `npm run typecheck` must stay clean; new files that need static copying (html/css) just live in `src/`. Architecture in ARCHITECTURE.md, setup in SETUP.md.
- Renderer is sandboxed (`sandbox: true`, `contextIsolation`, no `nodeIntegration`); all fs/dialog access goes through `preload.js` -> IPC handlers in `main.js` -> `fileAccess.js`.
- Security rules (see docs/SECURITY_ASSESSMENT.md): the main process owns trust. Never accept arbitrary paths from the renderer; new IPC must use `handle()` (sender check) and `fileAccess` (allow-list). No `'unsafe-inline'` scripts in the CSP. Pin exact dependency versions.
- Session restore: the renderer sends snapshots (open tabs, unsaved text, view state) to `sessionStore.js`, which writes `userData/session.json`. Main persists only paths already in the allow-list and re-approves them on load, so never let the renderer name paths to restore. Quitting does not prompt for unsaved changes (they are restored); closing a single tab still does. The file holds unsaved text in plain form.
- Language detection: file name/extension first, then content sniffing (`CONTENT_RULES` in `renderer/app.js`). Untitled tabs follow their content until the user picks a language by hand (`tab.autoDetect`).
- Document editing (docx/xlsx/csv/pdf): each kind lives in `renderer/editors/<kind>-editor.js`, registered with `CodePadEditors.register` and reached only through the view interface in `.claude/plans/binary-formats-design.md` (modules never call IPC). All document text from files is sanitized/inserted via `textContent`. PDF saving is Save-As-only and never targets the original; image-only PDFs are view-only. Known save limits (docx regenerated, no xlsx styling, no formula recalculation, whiteout is not redaction) must stay documented in README.
- Commands: every menu item/palette command is declared in a static table `shared/commands/<module>.commands.js` (id, title, menu path, order, accelerator, `when`). Main (`menuBuilder.js`) builds the native menu from the tables and sends only those ids in the `command` event; the renderer registers just the `run(ctx)` handlers with `CodePadCommands.register`. The id prefix need not equal the file name. There is no `menu` channel any more.
- Features (`renderer/features/*.js`) are self-contained scripts that touch the app only through `ctx` (built in `app.js`), the event bus, commands and panels; top-level code may only call `register` functions, everything else lives in `init(ctx)`/`run(ctx)`. Only `app.js`, `renderer/core/`, main glue and the shared infra files are edited for glue work. Never cache `ctx.editor` (it is a getter): split view is deferred and would change it to the focused editor.
- Settings: `shared/settingsSchema.js` is the single source for keys, ranges, defaults and the Monaco option each maps to; `app.js` applies mapped keys generically with `editor.updateOptions`. Main validates every patch (`settingsStore.js`); the renderer keeps a synchronous copy (`CodePadSettings`). Theme, minimap, wrap and sidebar no longer use localStorage.
- Stores holding paths (`session.json`, named sessions, `recent.json`) are HMAC-signed (`integrity.js`); a failed signature drops all paths and the folder and restores only untitled text. Restored/recent paths are re-approved through `fileAccess` by main from its own data. Windows ADS, reserved device names, trailing dot/space segments and filesystem roots are rejected.
- Encodings: `textCodec.js` (iconv-lite is the only added dependency); detection is BOM, UTF-16 NUL pattern, strict UTF-8, then `files.fallbackEncoding` (default windows-1252). Lossy saves never happen silently (`fs:write` returns `{ok:false, lossy:true}`). Lone-CR files are kept as `tab.eol = 'cr'` and converted at read/write time.
- Find in Files runs in a worker thread in main, always under the approved root, and never follows symlinks/junctions. No `shell.openPath`; Reveal uses `showItemInFolder` only. Clipboard permissions are granted only to the app window.
- Monaco is pinned to 0.52.2: 0.57+ changed worker bootstrapping, so upgrading requires reworking `MonacoEnvironment` in `renderer/app.js`.
- Must stay cross-platform (Windows/macOS/Linux): use `CmdOrCtrl` accelerators, `path` helpers, no OS-specific code without a `process.platform` guard.
- `asar: false` is deliberate: Monaco workers are loaded via `importScripts` from `file://`.
- Packaging via electron-builder config in `package.json`; installers are built per-OS.
- Local AI: node-llama-cpp 3.22.1 runs Qwen3-0.6B in one Electron utility process (`aiWorker.js`), supervised by `aiEngine.js`; `aiIpc.js` is the main-side composition root (loaded with `optionalRequire`; `registerAiStubs` answers the `ai:*` channels if it is missing). Summaries (extraction, map/reduce, number verification) run inside the worker. Design in `.claude/plans/local-ai-design.md`.
- Selectable summary models (plan: `.claude/plans/multi-model-preparation.md`, section 7c): ghost text always uses the built-in Qwen3; only summaries use the active model from `modelRegistry.js` (kinds builtin, gguf-file via native dialog, ollama-registry GGUF pulled by `ollamaPull.js`, huggingface, anthropic, openai-compatible; no Ollama daemon, other local models run through node-llama-cpp in a second engine). API keys live only in `secretStore.js` (safeStorage, no plaintext fallback, never sent back to the renderer); `models.json` is HMAC-signed. Remote models need one-time consent per model; a failed non-default model asks Yes/No to retry with the default. Remote network code is confined to `providers/*.js`.
- Network only in `modelDownloader.js`, `ollamaPull.js` (model downloads) and `providers/*.js` (summary APIs), all in main: pinned URLs, host allow-list per hop, pinned size and SHA-256. Never add model URLs, hosts or paths from the renderer; the worker has a network kill-switch and the CSP stays unchanged. `main.js --install-model` reuses the same downloader for the Windows installer.
- Right Arrow acceptance of ghost text relies on the Monaco context key `cpAiGhostAtEol` (an editor command, not a menu accelerator); never bind plain Right Arrow natively. `autosuggest.js` owns `quickSuggestions`/`suggestOnTriggerCharacters`/`wordBasedSuggestions`; `ai-suggest.js` owns `inlineSuggest`.
- Packaging the AI engine: `build.files` lists node-llama-cpp's dependency closure by hand and only the target's `@node-llama-cpp/*` engine package; `scripts/afterPack.js` asserts it. main withholds `ai.autoDownload` from aiIpc until `ai.setupPrompted` is true.
- Ghost text context (`shared/suggestText.ts`): header + enclosing scope + window before the cursor; the model never sees the text after the cursor (a stop string and the cleaner use it only to prevent repeats). Output is trimmed to a complete sentence/statement and dropped otherwise.
- Spelling is custom code with a SCOWL word list (`spellcheck.ts`, `src/dictionaries/en.txt`), never AI; squiggles only in plain text and Markdown. Grammar check and Rewrite/Restructure (`rewriter.ts`, `ai-rewrite.ts`) are on-demand AI commands that use the active summary model, show a diff, and change nothing until the user clicks Apply (one undo step); lossy chunks fall back to the original text.
- Trust stays in main (offensive review round): external links, remote-model add/setKey/setActive/consent, second-instance argv files and dropped paths are confirmed by native dialogs or bound to real events in main; the renderer never decides them. Signatures (`integrity.sign/verify`) always take a `purpose`; API keys are sealed to their host (`secretStore`); non-builtin GGUF files pass `ggufHeader.ts` before reaching the worker. `fileAccess` errors cross IPC only as fixed codes (`ENOENT`, `EACCES`, `EPERM`, `EEXIST`, `EIO`). Windows install is per-user only because `asar: false` leaves the app tree as plain files. See `SECURITY.md` and `docs/SECURITY_ASSESSMENT.md`.
- Closing a file-less tab with content (Untitled-N, summaries) asks Yes/No in `closeTabFromUi`.
